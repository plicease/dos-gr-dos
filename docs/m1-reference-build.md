# GR-DOS — M1 Reference Build

**Status:** Complete (2026-10-23)  
**Source:** vendored `v4.0` plus restoration commits `88eaca2` (hharte `1f50610`) and `ce69f7f` (`WR_PIIND`)

M1 reproduces the original MS-DOS 4.00 build with the original tools and boots the result. Its outputs are the reference that the Linux-native build (M2) is checked against. It runs locally only (decision 4).

## Running it

```sh
scripts/reference-build      # build into build/m1 (about 2.5 minutes)
scripts/reference-boot       # boot test of build/m1 in QEMU
```

### `scripts/reference-build`

1. `scripts/prepare-dos-tree` copies `v4.0/src` to `build/m1/SRC`, converting text files to CRLF and stripping `^Z` from `.SKL` files. Files with a binary extension (`EXE COM OBJ LIB SYS CPI`) or a NUL byte are copied unchanged. The vendored tree is not modified.
2. A generated `BUILD.BAT` replaces `SETENV.BAT`, with `LIB` and `INCLUDE` pointing at `TOOLS\BLD\LIB` and `TOOLS\BLD\INC` (the paths in `SETENV.BAT` are wrong), then runs `nmake` at `SRC`.
3. DOSBox-X runs headless (`SDL_VIDEODRIVER=dummy`, `-silent`) with `cycles=max`, `dos ver=5.0` and `lfn=false`.

No source changes were needed beyond the restoration.

### `scripts/reference-boot`

1. Takes the boot sector from the last 512 bytes of `BOOT/MSBOOT.BIN`.
2. Sets the physical drive number at offset `24h` to `00h`. MSBOOT's default BPB describes a hard disk (`80h`), and mformat updates the geometry but not this byte; without the fix the boot code reads the wrong drive and reports "Non-System disk or disk error".
3. `mformat -f 1440 -B` with that boot sector, **without a volume label**, since a label would occupy the first directory entry where the boot sector expects `IO.SYS`.
4. Copies `IO.SYS`, `MSDOS.SYS` (system, hidden, read-only), `COMMAND.COM` and a test `AUTOEXEC.BAT` that writes to `AUX`.
5. Boots headless QEMU from the floppy with COM1 written to `build/m1/boot/serial.log`, and passes when the end marker arrives.

## Results

- **Build:** all 62 binaries listed in `CPY.BAT` produced; no severe errors. Warnings are routine (`L4021: no stack segment`, MASM `A4100`/`A4057`/`A4016`). The `"Debug fields are being included"` message is an unconditional `%out` in `DOS/MSCONST.ASM` and appears in every build.
- **Determinism:** two clean builds produced byte-identical results for all 859 files the build creates or changes (outputs and intermediates), found by comparing contents with a freshly prepared tree. MASM listings (`.LST`) are excluded because their headers contain the build time. Manifest: [`m1/reference-build.sha256`](m1/reference-build.sha256), generated by `scripts/reference-build` as `build/m1/manifest.sha256`.
- **Boot:** reaches the prompt in QEMU. Serial output:

  ```text
  GRDOS-TEST-BEGIN

  MS-DOS Version 4.00

   Volume in drive A has no label
   Volume Serial Number is 2052-CF51
   Directory of  A:\

  COMMAND  COM     37556 10-23-26   5:38a
  AUTOEXEC BAT       155 10-23-26   5:38a
          2 File(s)    1348096 bytes free
          1 File(s) copied
  hello
  GRDOS-TEST-END
  ```

- **Not compared with retail MS-DOS 4.00 binaries**, which GR-DOS does not obtain or redistribute. lotharsm reports that an equivalent build matches retail except `SELECT.DAT`.
